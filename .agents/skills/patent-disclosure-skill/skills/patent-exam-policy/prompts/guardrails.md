# 政策简报 · 总则与边界

## 定位

本目录默认是 **给交底用的政策简报**：可选、须用户显式触发。  
对照国知局近期政策与审查口径，说明对**交底写法**（以及若有定稿，对**本稿**）的影响。  
**不**并入交底 Step 1–8，**不**并入通俗解读主流程。

**技能进化是旁路**：同一份信源表可以映射到交底包文件，但默认不改。须用户另外点名（「按简报改交底技能」/「采纳 E…」）才走 `apply_after_confirm.md`。

## 硬性禁止

- 把简报或进化旁路挂进每次交底或解读的默认步骤。
- 无人值守自动改任何 `SKILL.md` / `prompts/**` / `references/**` 并提交。
- 产出或建议「欺骗审查系统 / 掩盖违法采集或歧视决策 / 对抗审查大模型提示词攻防」类内容。
- 仅凭自媒体、二手转述、无准确 URL 的传闻写入简报主表或「建议改技能」项。
- 仅凭 B 源（发布会、答问、典型案例、司法解释）单独改技能。司法口径 ≠ 审查指南。
- 「全部采纳」时改到交底包白名单以外（含本包自身）。

## 简报关注什么（给交底作者）

- 充分公开、创造性叙事、与现有技术的差异化
- AI / 算法等申请客体、伦理 / 五条一款
- 实用新型明显创造性；外观局部 / GUI / 相似外观
- 专利法 / 实施细则中影响交底书式与客体的口径
- 附图 / 标记一致性、降低套话
- 已公布未施行的局令（施行日历，勿把未生效规则写成当前必须）

解读 / 答复 / 检索、司法口径、地方预审须知：记在「另议」，默认不改那些包，也**不要**当改技能的唯一依据。

对外表述优先用 **「政策简报」**；「政策雷达」视为同义。少用「规避对抗」。少把「技能进化」当主能力宣传。

交底定稿后的存在感：见 **`soft_nudge.md`**（低频至多一句；不挂进默认 Step）。

## 技能进化旁路 · 可写白名单（仅点名后）

仅下列路径（须写带包前缀的完整相对路径；主题先查 `references/topic_prompt_map.md`）：

- `skills/patent-disclosure/prompts/**`
- `skills/patent-disclosure/references/**`
- `skills/patent-disclosure/SKILL.md`

**例外（须该 E* 影响面=路由，且用户点名该编号，不随「全部采纳」）**：仓库根 `SKILL.md` 的路由/触发句。

**默认不改**：`skills/patent-reader/`、`skills/patent-search/`、`skills/patent-oa/`、`skills/patent-exam-policy/`。

## 简报结束时（默认，未改技能）

```
本稿为政策简报，对照官网口径，未改技能。
若要对交底技能做口径硬化，请另说「按简报改交底技能」或「采纳 E…」（须先有附录 E*）。
也可「沉淀到 docs/」将本稿复制到本包 docs/（仍不改 prompts）。
```

未收到改技能的确认前：**禁止** Edit/Write 技能正文（简报落盘到 `outputs/exam-policy/` 除外）。
