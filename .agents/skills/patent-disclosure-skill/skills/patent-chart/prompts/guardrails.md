# 对照表总则

## 定位

特征为行、证据为格的底稿。给人传、给人批注的主文件是 `对照表-{场景}-{时间戳}.xlsx`（总览热力 → 对照四列 → 明细全文；无效加路径备忘，FTO 加风险清单，侵权加证据缺口，审查答复加驳回映射）。

## 硬限制

- **禁止**输出无效 / 侵权 / 自由实施 / 可专利性法律结论。备忘只写覆盖情况与待核格。
- **派工**：先 `Read` 对方 `SKILL.md`，再按其流程跑**该包** `tools/`。
- 三件套不齐时只提问。收齐、`INTAKE_OK:1` 之后才解读、检索、填格、写 `intake.json`。
- 对照表派工解读时：Obsidian 未就绪则降级 `outputs/patent_reader/`，继续写；默认拆从属权利要求。
- **禁止**无出处格子写成「公开了」。强度「强」必须有可点开的 `source_url` 或段号+摘录。
- 无材料的格子标「无」，摘录留空。
- 全部特征都「强」时在待核清单警告过拟合，不删表。
- FTO / 侵权的「强」行仍须待人审（风险清单标「须人审」；总览该格附同一标记）。
- 场景读法不同，强度档位相同。无效：缺格只断该文献的单篇路径。FTO：该权任一特征未见，则对该方案不构成落入候选。侵权：弱格与未见格是待补证据，不是不侵权。可专利性与无效相同，缺格不是新颖性结论。
- 默认拆独立权利要求和从属权利要求。
- 右列不够时默认允许补搜；用户已指定全部对照对象则按用户给出的列填，不再检索。
- 材料不够就在对话里按题问；收齐、`INTAKE_OK:1` 之后才分析。不编造出处。

## 产出

只写 `outputs/patent-chart/{案件}/{会话}/`：`intake.json`（输入归档）、`对照表-{场景}-{时间戳}.xlsx`（主交付）、`chart.json`（机读底稿）。对话只给 xlsx 路径，不贴 `chart.json` 或摘录全文。不同次对照用不同会话目录。
