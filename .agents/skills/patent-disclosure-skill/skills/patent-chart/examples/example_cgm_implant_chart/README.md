# 对照表示例 · 连续血糖监测植入装置

对话演练材料，用来验证：材料不够时按题问、收齐后落盘、再派解读和补搜。  
**仅供技能功能测试**，不代表技术优劣或权利状态，不构成法律意见。

领域换成 CGM 植入器（防误触），不要用冷却壳体那套。左列示例号：`CN115969371B`（一种持续血糖监测器植入装置）。

开新对话，按下面三句依次粘贴。产出应在 `outputs/patent-chart/{案件}/{开场时间戳}/`。

## 第一句（触发问答）

```
帮我做一份权利要求对照表。我们在做连续血糖监测，植入器老是被误触，想看看这套方案站不站得住。材料还没齐，对比文件也还没定。
```

预期：先 `--alloc` 建会话目录；只问对照类型（1–5）；不要默认 FTO/侵权，不要直接填表。

## 第二句（只补左列，继续问）

```
1，可专利性。左边用已公开的 CN115969371B（持续血糖监测器植入装置）。
```

预期：左列锁定该公开号；**只问第三问（右列）**。不要写 `intake.json`，不要派解读，不要检索，不要填表。

## 第三句（收齐后才分析）

```
右边我还没有指定对比文件，请按这件专利的权要去检索补 D，连从权一起拆。
```

预期：`search_fill: true`，写入该会话 `intake.json`（`INTAKE_OK:1`），**这之后**才派专利解读（要 `claim_features.json`，默认含从权；Obsidian 未就绪也继续）和补搜 covers，再填格导出 `对照表-可专利性-{会话时间戳}.xlsx`。

若第一句就被直接出表、或跳过提问去编结构，说明 intake 没按对话收集走。
