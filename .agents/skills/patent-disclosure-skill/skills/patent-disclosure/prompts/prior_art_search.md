# 联网检索查新（Step 5）

按技术主题查找现有技术：一词一页、公布模式取第一页。著录检索（发明人/申请人清单）走检索包。本包引擎是 `cnipa_epub_search.py`。

## 必做时机

生成交底书全文之前或生成过程中执行；检索结论写入第一章 **1.1 现有技术** 及与本案的区别论述。

## 检索渠道（优先国知局公布公告站，再降级 WebSearch）

### A. 中国专利公布公告（优先，官方站点）

1. **站点**：[国家知识产权局 中国专利公布公告](http://epub.cnipa.gov.cn/)（`epub.cnipa.gov.cn`）。
2. **工具**（本仓库 **`skills/patent-disclosure/tools/crawl/`**）：**`cnipa_epub_search.py`** —— 一步完成公布站检索与结果解析（Playwright 过站点 WAF）；结果页 HTML 仅在内存中处理。成功时终端含 **`EPUB_NOTE:`** / **`EPUB_HITS_JSON:`**。
3. **专利类型过滤（与 intake 一致）**：官网首页勾选发明公布 / 发明授权 / 实用新型 / 外观设计。脚本参数 **`--type invention|utility_model|design|all`**（默认 `all`）。intake 默认为发明时传 **`--type invention`**；实用新型 / 外观分别传 `utility_model` / `design`。映射见 **`references/patent_type_search.yaml`** 与 **`tools/patent_type.py`**。
3b. **邻域召回 + 摘要精排（写 1.1 前必做）**

   1.1 只写精排池。技能不自建专利库、不用本地向量索引。当场搭「小类邻域」，再用 LLM 对照摘要精排。

   1. **第一轮（召回）**：首页 **3～4 个手段短语**（规则见下第 4 点；脚本 `home_max_terms` 默认 4）。**一词一页**，停留在 **公布模式**（带摘要卡片）。脚本在结果页用站点「每页10条」切换后取第一页（总数不足 10 则取全部）。成功时 JSON 含 **`ipc_codes` / `loc_codes`**；stderr 可能有 **`EPUB_CLASS_HINT: kind=ipc|loc codes=…`**。
   2. **抽出分类号**：发明/实用新型用 IPC 前缀（如 `B01J20`）；外观用 **LOC（洛迦诺）**（如 `26-05`）。取 **1～3 个**高频号。无分类号则跳过第二轮，仍按手段过滤第一轮。
   3. **第二轮（邻域快照）**：同一 `--type`，加 **`--class`**（`--ipc` / `--loc` 同义）。**一次命令 1 个最贴分类号 × 1 个最贴手段词**（`tools/crawl/cnipa_epub_wait.yaml` 的 `advanced_max_*`）。第二个号或第二个词再发一条命令，至多 **1～2 个手段词**。仍用公布模式 10 条首页。脚本走公布站 **高级查询**（分类号 + 名称），例如：

      ```bash
      python …/cnipa_epub_search.py --type invention --class B01J20 胺功能化
      python …/cnipa_epub_search.py --type invention --class B01D53 胺功能化
      python …/cnipa_epub_search.py --type design --class 26-05 台灯
      python …/cnipa_epub_search.py --type design --class 26-05
      ```

      命令行多传了会 **截断**（stderr `EPUB_HINT: truncated …`），不会直接 usage 失败。

      **第二轮失败与 0 条分开处理**：看 stderr `CNIPA_EPUB_ERROR:` 的 `stage=` 与 `hint=`。

      | stage | 含义 | 后续 |
      |-------|------|------|
      | `goto` | 页面打不开 | 高级查询：`hint=keep_round1`，保留第一轮，按下面保底回补 |
      | `gate` | 页到了但检索框不出现 | 同上 |
      | `submit` | 已提交但结果页不来 | 同上 |
      | （退出码 0 且 `EPUB_HITS_JSON: []`） | 真的 0 条 | 减少分类号或换更短核心词后重试，再按下面保底处理 |

      | 场景 | 正例 | 反例 |
      |------|------|------|
      | 第二轮超时 | 导航失败，保留第一轮 | 写成「检索不到」 |
      | 检索渠道 | 公布公告站 | 需登录的专利检索及分析系统 |

   4. **候选池**：两轮去重（`pub_number`）；优先同分类号。
   5. **Google Patents（可选补充）**：外网可能被墙。**至多尝试一次** WebSearch / 浏览器，查询串用 `patent_type.google_patents_websearch_query(核心词, type, class_codes)`（发明/实用含 `CPC=…/low`，外观带 LOC 号 + `type:DESIGN`）。超时、被墙、0 条 → 跳过，不阻塞 1.1。有命中可并入候选池，中国专利 URL 仍抄国知局 `link`。
   6. **精排（必做，LLM 打分）**：对候选每条 **`abstract`** 对照本案「**技术问题 + 手段**」打 0–5 分（推理过程内完成）：

      | 分 | 含义 |
      |----|------|
      | 5 | 同一技术问题，手段/模块明显重叠 |
      | 3 | 同领域、手段相关 |
      | 1 | 仅关键词撞车 |
      | 0 | 远领域噪声 |

      无摘要的条目先补详情/Google 再打分，补不到则标「无摘要」且不得超过 2 分。取 **Top 6～8** 作为精排池；**D1 从精排池选**。1.1 只写精排池（可再按分类号回补到约 4～6 条）。
   7. **条数保底**：精排后仍 **<4 条** → 从候选池里捞 **同一 IPC/LOC**、分数≥3 的补到约 **4～6 条**。还不够 → 该类下少用或不用名称词再查一次（仅 `--class`），或带上 HINT 里的相邻号。仍然少 → 1.1 如实写「检索范围内近邻较少」。邻域空时门禁可「不过」仍成文。

      条数不够时写「近邻较少」。公开号、URL、D1 只写 JSON 或已打开页面里有的。
   8. **本包渠道**：公布公告站（及可选 Google Patents 补充）。同族只作背景，IPC 用 HINT 里的号，精排在本轮摘要上完成。

   | 场景 | 正例 | 反例 |
   |------|------|------|
   | 1.1 写入范围 | 精排池 6～8 条 | 第一轮多词合并全集 |
   | 公布模式 | 每页 10 条、第一页 | 列表模式追 20、翻完全部分页 |
   | 第二轮命令 | `--class B01J20 胺功能化`（1×1） | 一条命令堆 3 个分类号 × 3 个词 |
   | D1 来源 | 精排池里摘要最贴的一篇 | JSON 数组第 1 条或公开日最新 |

4. **国知局检索词（生成阶段必做，须在拼 Bash 之前完成）**

   - **拆分责任在 Agent**：在生成/构造命令阶段，从本案技术方案、专利点或用户主题中归纳 **3～4 个手段短语**（脚本首页上限 `home_max_terms` 默认 4），**仅用 ASCII 空格分隔**，再写入 `cnipa_epub_search.py` 的参数。每一单位为宜 **有检索意义的语义块**：专业术语、名词短语、名动组合（如「批量调度」「异构调度」）、业内固定搭配。4 个狠词优于 8 个泛词。
   - **Agent 执行时**：**一次进程传入全部检索单位**（多个 argv 或空格分隔均可）。脚本在**同一浏览器**内一词一查再合并，公布模式每页 10 条。若单次环境超时，再拆成至多两批，每批仍共用一个浏览器。
   - 示意（须按本案替换；**一次调用、多个词**；类型按 intake）：

     ```bash
     python …skills/patent-disclosure/tools/crawl/cnipa_epub_search.py --type invention 知识库 检索增强 大语言模型
     ```

   | 场景 | 正例 | 反例 |
   |------|------|------|
   | 检索词 | `知识库 检索增强 大语言模型` | `"知识库检索增强大语言模型"` 整句当唯一参数 |
   | 词粒度 | 「异构调度」 | 单独「系统」「方法」 |
   | 进程 | 一次调用传入 3～4 个词 | 每个词单独起一个 Playwright |

   - 脚本不做自动分词或自动拆长中文；确需整句一次 AND 检索，改用 **`cnipa_epub_crawler.py`** 单传一句。

5. **执行方式**（Step 5 在读完本文件后先探测，再检索）：

   ```bash
   python skills/patent-disclosure/tools/browser.py --probe
   ```

   - `--probe` 的 stdout JSON：`playwright=false` 时**本会话最多一次** `pip install playwright`（或 `pip install -r requirements.txt`），再 `--probe`。
   - `ok=true`（已有 Chrome / Edge / 自带 Chromium）→ **直接检索**。
   - `ok=false` 且已有 Playwright 包、本机无 Chrome/Edge 时，才允许**一次** `python -m playwright install chromium`，然后再检索。
   - 探测或启动仍失败 → 进入 **B**（WebSearch）。

   ```bash
   python skills/patent-disclosure/tools/crawl/cnipa_epub_search.py --type invention 词甲 词乙 词丙
   ```

   - **合并**：一次调用若 stderr 含 **`EPUB_MERGE:`**，以 **stdout** 上**唯一一行** **`EPUB_HITS_JSON:`** 为准（脚本已按 `pub_number` 去重）。仅当拆成多批调用时，Agent 再按 **`pub_number`**（无则 **`link`**）合并。
   - **`cnipa_epub_search.py`** 按空白拆段、**同一浏览器**内一段一查并去重（**stderr** 可出现 **`EPUB_MERGE:`**）。
   - 成功时 **stdout 仅一行** **`EPUB_HITS_JSON:`** + JSON 数组（UTF-8，含中文 `abstract`、**`ipc_codes` / `loc_codes`**）；**`EPUB_PROGRESS:`** / **`EPUB_MERGE:`** / **`EPUB_NOTE:`** / **`EPUB_HINT:`** / **`EPUB_CLASS_HINT:`** / **`BROWSER:`** / **`CNIPA_EPUB_ERROR:`** 等在 **stderr**（多为 ASCII 机读标记）。`EPUB_PROGRESS:` 标明当前卡在 `goto` / `gate` / `submit` 哪一段。
   - **stderr ≠ 失败**：退出码 **0** 且 stdout 有 `EPUB_HITS_JSON:` 即为成功。PowerShell 把 stderr 显示为 `NativeCommandError` 或中文乱码时，仍以该行 JSON 为准。脚本已 UTF-8 输出。
   - 解析命中时以 **stdout 该行 JSON 为准**。
   - 将 JSON 中可核验的公开号、标题、**国知局站点内详情链接**写入查新笔记与 1.1（见下 **`abstract` 必用**）。
   - **三种失败，分开处理**：
     1. **导航失败**（退出码非 0，stderr 有 `CNIPA_EPUB_ERROR:` `stage=goto|gate|submit`）：看 `hint=`。`skip_epub`（通常是第一轮首页打不开）→ 才进入 **B**。`keep_round1`（通常是第二轮高级查询）→ **保留第一轮 JSON**，按 3b.4 回补。
     2. **真 0 条**（退出码 0，`EPUB_HITS_JSON: []`）：换词 / 减分类号 / 回补。
     3. **无 Playwright 且安装失败**：进入 **B**。探测或启动仍失败 → **B**。
   - **降级条件**（满足才进入 **B**）：第一轮 `hint=skip_epub`、无 Playwright 且安装失败、第一轮 stdout **无** `EPUB_HITS_JSON:`、第一轮 **`EPUB_HITS_JSON` 为空数组**且无法按分类号回补、或条目经人工核对明显与主题无关。第二轮超时/导航失败单独不触发 §B。退出码为 0 且 JSON 非空时，stderr / 乱码 / NativeCommandError 仍算成功。等待上限见 `tools/crawl/cnipa_epub_wait.yaml`。

6. **`abstract` 字段（国知局条目，规定必用）**

   若 **`EPUB_HITS_JSON`** 中某项含非空的 **`abstract`**（解析自公布站结果页摘要），对该条专利须同时遵守：

   - **必用**：查新笔记、交底书 **1.1** 中对该专利的技术方案概括、应用场景与局限性分析，须先基于对该 `abstract` 的完整阅读与理解后再撰写。
   - **充分理解**：在写入 1.1 或查新笔记前，Agent 须在推理过程内明确：摘要所涉技术领域、解决什么问题、核心手段/模块、主要效果或流程；若摘要与标题存在差异，**以摘要为准**概括该技术。
   - **正文呈现**：交底书 1.1 用自己的话压缩为「方案概括 + 应用 + 缺点/局限」；查新笔记可保留稍长的摘录供自用核对，并标注来源于公布站摘要。
   - **缺失时**：若某条 JSON 无 `abstract` 或为空，须在查新笔记中注明「该条无摘要字段」，并改用详情页或 Google Patents 等可核验来源补全理解后再写 1.1。

   | 场景 | 正例 | 反例 |
   |------|------|------|
   | 1.1 技术方案 | 消化摘要后用自己的话写「方案 + 应用 + 局限」 | 整段粘贴官方摘要，或脱离摘要杜撰手段 |
   | 证据级别 | 摘要级判断写成摘要级 | 写成「已核实全文」 |

7. **链接与著录**：`EPUB_HITS_JSON` 命中项在 1.1 的「来源链接」**直接使用 JSON 的 `link` 字段**（国知局公布站 `epub.cnipa.gov.cn`）。Google Patents 仅用于 **§B** 降级检索所得条目，或 JSON 无 `link`、仅知 `pub_number` 时的备选取址（如 `https://patents.google.com/patent/CN…/en`）。公开号与 URL 须对得上 JSON。页面可访问且与著录项一致之后，才把该 URL 写入 1.1。

### B. Google 学术与 Google Patents（降级 / 补充）

在 **A 不可用或结果不足**时启用。类型过滤能力见 **`references/patent_type_search.yaml`**：

1. **中文文献与学术**：[Google 学术搜索](https://scholar.google.com)（`scholar.google.com`）。
   - 界面上没有发明 / 实用新型 / 外观设计勾选；类型案件仍用技术关键词检索论文等 NPL。
   - 用中文关键词、技术方案核心术语、应用场景；可组合 2–3 组查询。
   - 通过 WebSearch 或浏览器检索；优先可打开且与标题/作者匹配的链接。
2. **专利公开文献（补充）**：[Google Patents](https://patents.google.com/)。
   - **发明**：界面/参数倾向 **Patent（`type=PATENT`）** + `country:CN`；公开号常见 `CN…A` / `CN…B`。第二轮分类号可拼 `CPC=B01J20/low`（见 3b.5，外网不通则跳过）。
   - **实用新型**：用 Patent 域 + 关键词「实用新型」或公开号 `…U` 收窄，类型过滤仍以国知局 A 渠道为准。
   - **外观**：勾选 / 使用 **Design（`type=DESIGN`）** + `country:CN`；公开号常见 `…S`。可把 LOC 号（如 `26-05`）当作补充词。
   - 每条使用稳定著录页 URL；查询串可参考 `tools/patent_type.google_patents_websearch_query`。
3. **其它来源**：英文文献、非中国专利等可继续用 Google Patents、出版社页面、DOI、arXiv 等 + WebSearch。
4. **关键词构造**：技术方案核心术语、应用场景与方法名称，可组合 2–3 组查询。

## 分析要求

对检索到的、与方案高度相关的现有专利或公开文献逐项概括：

- 专利号 / 文献标识
- 技术方案要点（若为国知局 JSON 且含 `abstract`，要点须与摘要理解一致，见上文「`abstract` 必用」）
- 应用场景
- **局限性**
- **公开源 URL（必填）**：每一条附带至少一个可公开访问、与著录项一致的链接，写入查新笔记与交底书 1.1。页面可访问且对应同一文献之后，才写入。公开号、URL 只写 JSON 或已打开页面里有的。

### 链接来源与格式（须准确）

| 类型 | 推荐 URL 形式 | 说明 |
|------|----------------|------|
| 美国等专利（公开出版物号） | `https://patents.google.com/patent/US20240118920A1/en` | 将 `US20240118920A1` 替换为实际公开号；以 Google Patents 页面能打开且标题/摘要匹配为准。 |
| 中国专利（**§A 国知局 JSON 命中**） | JSON 的 **`link`**，如 `http://epub.cnipa.gov.cn/patent/CN119781913A` | 1.1「来源链接」照抄 `link`。 |
| 中国专利（**§B / WebSearch 补条**） | `https://patents.google.com/patent/CNXXXXXXXXXA/en`（或对应 B 型等） | 仅无国知局 `link`、经 §B 检索所得条目使用。 |
| 学术论文（含 Scholar） | Scholar 条目页、出版社官方页或 **`https://doi.org/10.xxxx/...`** | Scholar 链接若重定向或镜像，以最终可长期解析的 DOI/出版社页为准。 |
| arXiv 预印本 | `https://arxiv.org/abs/2008.09213` | `abs` 页为规范条目页。 |
| 期刊 / 会议 | 出版社 DOI：`https://doi.org/10.xxxx/...` 或官方摘要页 | 以 DOI 解析后页面与文献一致为准。 |

## D1 锁定与区别特征 Fk（写 1.1 前必做）

检索完成后先把「跟谁比、差在哪」写进内部稿 **`查新与区别定位_{YYYYMMDDHHmmss}.md`**（用户索要时可给）。这是审查三步法的成文骨架：主比对钉一篇出发点。成文纪律见 **`invention/disclosure_builder.md` §7.10**。

本包查新默认是一词一页 + 摘要。定位稿须标明**证据级别**（摘要 / 公开文本未通读 / 领域较远）。摘要级判断保持摘要级表述。精排池与定位稿就绪之后，才写 1.1。

### 1. 选出 D1（最接近的现有技术）

**D1 = 技术方案最接近的一篇**，作为逐特征主表的出发点。

- `EPUB_HITS_JSON` 没有公开日字段，脚本也不做相关度排序；数组顺序只是页面顺序 + 去重 + 多词合并。先按上文 **3b.6** 对摘要打分，从精排池里选 D1。
- 选定优先级：① 精排分最高且解决同一技术问题、手段/模块相似；② `abstract` 与本案方案重叠面最大；③ 覆盖本案拟保护要点最多；④ 同族或同申请人多篇取**代表篇**，其余作背景。
- 须写一句**选定理由**（为什么是它，而不是另一篇）。两篇几乎一样近：仍先定一篇为 D1，另一篇标 **D2**。
- 其余条目在 1.1 作技术背景。D1 公开号只写精排池里有的；未钉住时写 **D1=未钉住**。

| 场景 | 正例 | 反例 |
|------|------|------|
| 选 D1 | 精排分最高、同一技术问题 | JSON 下标第 1 条，或五篇平均当 D1 |
| 不过成文 | 远领域当背景，区别对材料/常规写 | 指定不相干公开号当 D1，或空喊「创新性强」 |

### 2. 逐特征比对表（产出 Fk 编号）

**主表只对 D1。** 按**技术维度**逐行比对，给每条实质区别一个编号 **F1、F2…**（全案唯一、口径唯一）。**编号在表里完成定义**：单独成「编号」列，「本案怎么做」写满构造/机制。能进这张表的都是区别。有 D2 补行时「对比文献」列标 `D2（补行，组合风险）`。

**定位稿**可继续密写 Fk。**交底正文**的出场纪律见 **`invention/disclosure_builder.md` §7.10「Fk 出场」**：表 + 表后一览定义一次；1.2 / 二 / 四说人话；三 / 六用中文构造；5.1 用 Fk 作条目标签并复述全文。列名用「本案怎么做」。

| 编号 | 对比点 | 对比文献 | D1 / 对比文献怎么做 | 本案怎么做 |
|------|--------|----------|---------------------|------------|
| F1 | 节点资源刻画 | D1 | 单一 CPU 负载阈值 | 对节点 CPU/内存/IO 做窗口平滑聚合，得到资源画像 |
| F2 | 重排时机 | D1 | 每次派发前均重排 | 间隔阈值与分数变化阈值双条件才触发重排 |
| F3 | 重排范围 | D1 | 全队列 | 重排只作用于队列窗口子集 |
| F2 | 窗口平滑（组合风险） | D2（补行，组合风险） | 公开指数滑动平均 | 本案窗口平滑与间隔/分数双阈值触发联用 |

表后写 **特征一览**（后文只用这些中文简称，F 号最多句末括注）：

- F1 资源画像：对节点 CPU/内存/IO 做窗口平滑聚合
- F2 双阈值触发：间隔与分数变化双条件才重排
- F3 窗口子集：重排只作用于队列窗口而非全队列

**D2 补行不是第二套 D1**：仅当「D1 没有、本案有、且 D2 公开了相近手段、审查时可能拿来组合」时才加行。无组合风险则主表只对 D1。「本案怎么做」用中文复述联用的是哪段构造。

维度须是**技术维度**（实用新型比部件与连接关系；外观比造型、图案、色彩要点，可不用 Fk 编号）。比对维度是部件/模块/步骤，列名用「本案怎么做」。

定位稿文首用一行写清：**门禁状态**（过 / 带疑点过 / 不过）+ **证据级别** + D1（及可选 D2）公开号。不过且未钉住出发点时写 **D1=未钉住**。

### 3. 门禁（三态；三态都进 Step 6）

轻量查新锁「最接近」证据有限。门禁管的是**创造性骨架写到哪一档**，三态都进交底成文。写得出具体区别时，用「带疑点过」并标明证据级别。

| 状态 | 何时 | 下一步 |
|------|------|--------|
| **过** | D1 与本案同一问题、手段/模块重叠清楚；至少一条 Fk 能落到 D1 的**具体**不足 | 进 Step 6；预览点名 D1 与 Fk |
| **带疑点过** | 仍能点名一篇出发点并写出至少一条指向该篇（或 D2）的实质区别，但证据不足或出发点不稳——例如仅摘要、两篇几乎一样近、命中偏远领域、开创性而最近的一篇仍较远 | 进 Step 6；定位稿与预览写出不确定处；交底 1.1 标明摘要级。实用新型结构区别能指到具体文献时**优先用本态** |
| **不过** | 写不出任何一条能落到**具体对比文件**不足上的实质区别——开创性、检索只有远领域噪声、或两组发明点其实该拆案 | **仍进** Step 6 / 7。创造性论述**降级**（见下）；预览开头写明未钉住最接近对比文件 |

**「不过」仍成文，降级规则**：

- 1.1 检索结果如实当背景（远领域噪声就当背景）。写清「本次未钉住可作最接近现有技术的对比文件」。未钉住时写 **D1=未钉住**；公开号、URL 只写 JSON 里有的。
- 区别对「材料里的现有做法 / 本领域常规」写，Fk 仍在 1.1 一览与 5.1 编号，并标明**未经对比文件钉死**；1.2 / 二 / 四仍说人话。
- 1.2 指到上述现有做法的具体不足。
- 该拆案：先写一篇，5.1 写明无共同必要特征，预览建议拆，继续 Step 6。

另：

- 某条 Fk 的手段词在本轮检索里从未被检索词覆盖 → 就该 Fk 的手段词补一轮检索（规则同上文第 4 点），再判断它是否站得住（可因此从「不过」升到「带疑点过」）。
- 某条 Fk 与 D1 高度重合、只剩参数取值差异 → 如实记录，交由第五章按 **§7.10** 归入**附加/优选特征**。

过 / 带疑点过：1.2 每条缺点应能在表里找到对应的 D1 或 D2 一侧。不过：1.2 对材料或常规做法。

## 记录习惯

便于写进交底书：保留专利号、标题、消化摘要后的一两句方案概括（有 **`abstract`** 时概括须可追溯至该摘要）；每条另起一行或表格列给出「来源 URL」。

### 1.1「检索说明」写法（交付正文，必遵）

写入交底书 **1.1** 开头的「检索说明」时，面向代理人/审查员表述。

- **须写**：实际使用的公开数据库或渠道名称（如「国家知识产权局专利公布公告系统」）、本案主要检索词；若做了分类号收口，可写 IPC 或外观 LOC（如「在 B01J20 类下」）。若部分条目经 Google Patents 等公开页复核著录项，可一句带过。
- **示例（须按本案替换检索词与渠道）**：

  > 检索说明：在**国家知识产权局专利公布公告系统**及 **Google Patents** 中，以「批任务调度」「异构集群调度」「任务队列重排」「负载感知调度」等为检索词进行检索；部分条目的公开文本与著录项以 Google Patents 页面复核。

| 场景 | 正例 | 反例 |
|------|------|------|
| 1.1 检索说明 | 国家知识产权局专利公布公告系统 + 检索词 | `cnipa_epub_search.py`、Playwright、是否降级 |
