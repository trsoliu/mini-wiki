# 边界与输入录入（Step 1）

## 用途

在开始专利挖掘与交底书撰写前，用**少量问题**收敛案件边界。信息不全时可跳过，由 Agent 后续推断并**注明假设**。

## 可选开场

```
为便于挖掘专利点与组织交底书，先确认几项边界；可跳过，将按已有材料推断。
```

## 问题序列

### Q1：技术主题或产品模块

```
请用一句话描述本方案所属技术主题或产品模块，例如「多模态检索排序」「工业质检缺陷分级」「集成式电驱桥壳体」。
```

### Q2：专利类型（发明 / 实用新型 / 外观设计）

```
本案倾向哪一类专利？发明 / 实用新型 / 外观设计 / 暂不确定
```

**默认规则（硬性）**：

- 用户**未显式**指定发明 / 实用新型 / 外观设计时，**统一默认 `发明`**（`invention`），并在汇总中写明「专利类型：发明（默认）」。
- 仅当用户明确说「实用新型」「外观」「外观设计」等时，才切换类型。
- 「暂不确定」或跳过 Q2 → 仍按**发明**推进；可在材料扫描后再用下方「反问」校正。

**与权利要求形态区分**：方法 / 系统 / 装置属于**权利要求书式倾向**（见发明模板 §7.6），**不是**本问的专利类型。若用户只答「方法/系统」，仍默认专利类型为发明。

### Q3：文头联系人

```
交底书文头的技术联系人是否需要占位？需要则提供姓名/电话/邮箱；不需要则全部写「待填写」。

未提供发明人、申请人或联系人时：文头写「待填写」，继续挖点与成文。后续案卷分诊记 `human_fact` / `ask_human`，**`blocking: false`**，不得因此卡住申请文件或后续轮次。
```

## 汇总

将已确认项用 3–6 行 bullet 复述给用户（**必须含专利类型**，含默认值），再进入 `project_scan.md`。

类型路由（汇总后）：

| 专利类型 | 后续特化 |
|----------|----------|
| 发明（默认） | `skills/patent-disclosure/prompts/invention/` |
| 实用新型 | `skills/patent-disclosure/prompts/utility_model/` + `prompts/fill_structure_schema.md`（含 **`figure_plan.yaml`**） |
| 外观设计 | `skills/patent-disclosure/prompts/design/` + `prompts/fill_appearance_schema.md`（含 **`figure_plan.yaml`**） |

查新时把类型传给检索工具：`--type invention|utility_model|design`（见 `prior_art_search.md`）。

## 总结性反问（材料更偏实用 / 外观时）

在 **Step 1 汇总之后**，或 **Step 2 扫描 / Step 6 预览** 发现材料明显更偏结构或外观、且当前仍为默认「发明」时，**须反问一次**（勿反复打断）：

```
当前按「发明」推进。材料更像：
- 产品形状/构造改进（卡扣、散热布局、支架等）→ 是否改为实用新型？
- 外观造型/图案/配色 → 是否改为外观设计？
回复「维持发明」或指定类型即可。
```

用户确认后再切换类型与模板；未回复则维持发明。
