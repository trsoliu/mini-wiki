# 保护型 1+N · 立项说明

矩阵已落盘。**先写出推荐方案，等人点头后再分头写交底，不要直接批量开写。**

同一轮写两份，节点 id 与「这一轮写不写」必须一致：

- `outputs/{案件}/fence/family.yaml`：给校验和分件用  
- `outputs/{案件}/fence/专利布局.md`：给人看、给对话确认用  

禁止用脚本从 yaml 生成 md，禁止出 HTML，禁止 Mermaid / 程序画图。结构靠标题层级：核心 → 场景 / 改进 / 上下游。

## 立项（只做保护型）

只根据分解、突围、矩阵、已有交底与材料，不编新结构。`strategy` 只能是 `protective`。

- **核心 1 件（默认，最多 2）**：沿用首篇类型。`slim_note` 写清从首篇第五章/实施例**拿掉**哪些点；可放从属的进 `dependents_hint`。  
- **外围 N**：三类，互不吞并：
  - `scenario`：应用场景 / 工况 / 产品形态  
  - `improve`：改进结构或参数组合（须能单独实施）  
  - `chain`：上下游（检测、接口、制备、使用）  
- 外围若只是核心独权下位 → **不要**单独立节点，写进核心 `dependents_hint`。  
- 矩阵 `dense` 或 `material_ok: false` → 可以出现在方案里，但 `write_this_round: false`，说明稿写进「这一轮先放下」。  
- 这一轮要写的：核心 1 + 外围 ≤3（`sparse` 且材料够的优先）。  
- `geography_note` 写明：本趟只出中国交底。

落盘 `family.yaml`。`title` 必须含「专利布局」，并点明保护型 1+N。


## 说明稿章节（必须按此写）

一级标题固定为下列顺序，**勿增删、勿改名**：这一轮打算写、这一轮先放下、核心、外围、技术功效矩阵、**立项校验**、请确认。  
`## 立项校验` 在本步可先写占位句「评分后回写本段」；**必须等 `score.md` 跑完作答并回写表格与结论后**，说明稿才算交完。禁止把该章写成「高价值达标」或国知局统计结论。

对照 yaml **直接写** `专利布局.md`，把必要特征、从首篇拿掉什么、为何单独立项写开，不要藏在字段名里。人读用语：

| 不要写 | 改成 |
|--------|------|
| 本趟建议成文 | 这一轮打算写 |
| 本趟不成文 | 这一轮先放下 |
| 核心缩权 | 从首篇拿掉 |
| 从属退路 | 可放从属的 |
| 密 / dense | 公开方案已较多 |
| 疏 / sparse | 仍有落点空间 |
| 未查 / unchecked | 尚未检索 |
