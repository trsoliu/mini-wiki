# 保护型 1+N · 立项后弱校验

立项说明已落盘（`family.yaml` + `专利布局.md` 除校验表外的章节）。本步**不是**旁路第一道门，也不决定要不要问用户做布局。用来检查：有没有至少 1 个可写外围、矩阵不是挤的、材料够不够。

对照**已落盘交底、family.yaml、matrix.yaml** 与分解/突围，逐题给 `0|1|2` 或 `score: null`（未决）。正分必须 `evidence` 引用章节、矩阵格子或节点 id，不编。经济维材料没写 → 未决。

默认表 `references/scorecards/gbt42748_fence.yaml`（案件有 `fence_scorecard.yaml` 则用那份）。分件门槛看围栏维：至少一篇可独立外围（F1=2）、材料撑得住（F3=2）。法律/技术可填作稿件质量证据，**不挡**过门槛。经济未决允许，**不能**单靠经济分算过门槛。

**禁止**把本表说成资产评估、国知局「高价值发明专利」统计达标，或在说明稿/对话里写「高价值达标：是/否」。

写 `outputs/{案件}/fence/scorecard.yaml`：

```yaml
scorecard_id: gbt42748_fence
disclosure_md: outputs/…/….md
items:
  F1: { score: 2, evidence: "P1 n_class=improve，与 C1 必要特征不吞并" }
  F3: { score: 2, evidence: "结构图已有铰链局部" }
  L3: { score: 2, evidence: "首篇 1.1 …" }
  E1: { score: null, evidence: "材料未写产品寿命" }
```

跑：

```bash
python skills/patent-disclosure/tools/fence/check_scorecard.py -i outputs/{案件}/fence/scorecard.yaml --case-dir outputs/{案件}
```

以 `SCORECARD_OPEN:` / `SCORECARD_BORDERLINE:` / `SCORECARD_JSON:` 为准（作答合法时退出码为 0；是否过门槛看 `SCORECARD_OPEN`）。
