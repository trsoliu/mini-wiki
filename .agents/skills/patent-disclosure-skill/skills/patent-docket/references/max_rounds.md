# 轮次上限

`config.yaml`：`max_rounds` 默认 **3**。校验脚本读该值；对话里用户说「再来一轮」也不得超过。

## 什么算一轮

| 事件 | 轮次 |
|------|------|
| 从零：交底初稿完成 **并且** 首套申请文件（含问题清单）落盘 | 记为第 **1** 轮，写入 `rounds[]` |
| 已有交底、本包才出的第一套申请 | 同样第 **1** 轮 |
| 已有申请、本案卷第一次分诊 | 当前已有申请视为第 1 轮已完成；后续派工再出的申请为第 2、第 3 轮 |
| 分诊后改交底或只改申请，并再次交付申请文件 / 新问题清单 | `round` 加 1 |

`docket.yaml` 的 `round` 表示**正在进行或刚完成的轮次编号**（1–3）。`rounds` 数组长度不得超过 `max_rounds`。

## 停

- `round == max_rounds` 且本轮申请已核过清单 → 进入 `terminal_max_rounds`（仍有未关条目）或 `terminal_complete`（无 open）。
- 未满 3 轮但无 open 条目 → `terminal_complete`。
- 阻塞问人超过本会话可等的范围 → `terminal_blocked`，不消耗「空转轮次」，但不得假装已闭环。

## 禁止

- 同一轮里反复派工交底却不出新申请（纠正交底后必须申请手）。
- 把机器检查失败循环重跑三次却不改根因，仍计轮次；第三次必须停并 `ask_human` 或 `defer`。
