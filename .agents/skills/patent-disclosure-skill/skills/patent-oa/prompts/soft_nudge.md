# 审查答复回复末尾 · 库厚度提示（可选 · 仅对话）

**不得**写入意见陈述草稿 `.md` 正文。  
本轮若已在做案例入库或实务书蒸馏，**禁止**再提示「去入库 / 去蒸馏」。

审查答复的主场景是**问和答**（读通知书、出草稿、换策略、确认后出 Word）。案例库与经验手册是让下次检索更准的配套；用户未必知道可以说「案例入库」「实务书蒸馏」。

## 何时检查

审查答复流程中，**每次**面向用户的完整回答末尾（问答、出草稿摘要、换策略新稿、确认后出 Word）。先跑只读统计（**不要**为此刷新索引）：

```bash
python skills/patent-oa/tools/refresh_vault.py --inventory
```

看 JSON：`nudge`、`below.history`、`below.playbooks`、`counts.history`、`counts.playbooks`。  
默认阈值：**可检索历史案 < 3** 或 **经验手册 < 3**（脚本 `--min-history` / `--min-playbooks`，一般不必改）。

## 抑制条件（有一条则本轮不提示）

- 本会话回复里**已经**出现过本提示。  
- `nudge` 为 `false`（两边都已达阈值）。  
- 本轮用户意图就是入库或蒸馏（正在按 `ingest_case.md` / `ingest_playbook.md` 执行，含刚完成的报告）。  
- 用户明确说过「别再提醒入库」一类话。

## 话术（整段最多 2 句，放回复末尾）

按 `below` 选用，可把 `counts.*` 填进句中；允许轻微改写。

**仅历史案不足：**

> 补充：现在可对照的历史案还不多（N 篇）。若有旧通知书和答复 PDF，可以说「案例入库」并给出路径，脱敏进库后，下次写草稿能对上旧打法。

**仅手册不足：**

> 补充：经验手册还很少（N 本）。若手头有审查答复实务书（本地 PDF/md，不要网址），可以说「实务书蒸馏」并给出路径，先预读再蒸进库，写答复时按缺陷查阅。

**两边都不足：**合成一段，仍不超过 2 句，两件事都点到即可。

**禁止**：展开安装/命令教程、恐吓「不入库会驳回」、超过 2 句、把提示写进草稿文件。
