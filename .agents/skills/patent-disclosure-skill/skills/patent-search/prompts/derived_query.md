# 单图 / 权要 → 公布站检索式

用户给**一张图**或**一段权利要求**、要求查类似专利时使用。先读图或权要，抽出名称词、摘要特征词和分类号，再调用 `cnipa_search.py`。

这是关键字代理：把图或权要收成公布站名称/摘要检索式。对话与报告沿用脚本写入的免责声明（名称/摘要关键字，漏检可能较高）。

填表语法见 `prompts/patent_search.md`「填表语法」。

## 必要输入

二选一（可再叠加发明人、申请人等著录字段）：

- **单图**：产品照、结构图、线稿或界面截图一张。用 Read 看图，公布站只收检索式。
- **权要**：独立权利要求或保护范围草稿。读文本，收成名称词和 2～4 个摘要词再填。

缺图且缺权要时，退回 `patent_search.md` 普通著录检索。

用户说「用这张图查一下」：看图推断 `--type` 后直接检索。

## 单图：`--type` 取三类之一

`--derived-from image` 时 `--type` 为 `design` / `utility_model` / `invention`（`all` 会被脚本拒绝）。

### 类型怎么定

1. **用户说了听用户的**（外观 / 实用新型 / 发明）。`--type` 用口头指定。
2. **没说则看图推断**，立刻检索，并加 `--type-inferred`（报告写入推断说明）：

| 图面 | `--type` |
|------|----------|
| 产品照、效果图、包装、造型线稿 | `design` |
| 爆炸图、剖视、装配、零件图、CAD 工程图 | `utility_model` |
| 流程图、系统框图、算法示意 | 图明确是方法/系统流程 → `invention`；分不清产品界面还是框图时问一句再查 |
| 产品照但功能结构也很突出、两种都像 | 默认 `design` |

3. 推断后在对话和报告里让用户看见类型。产品照默认外观时，`--type-inferred` 会写入：「未指定类型，按产品外观检索；若要查结构请说实用新型」。

权要按权利要求主题选 `--type`，可以用 `all`。

## 读图分叉（同一脚本，两套抽词）

定下 `--type` 之后，只走对应口径。

`--title` 用 2～6 字产品或装置通称。首次摘要词 2～4 个。

| 场景 | 正例 | 反例 |
|------|------|------|
| 外观摘要 | `折叠 and 弧面` | `卡扣 and 铰链` |
| 外观分类号 | `09-03` | `B65D` |
| 实用新型摘要 | `卡扣 and 铰链` | `弧面 and 对称` |
| 实用新型分类号 | `B65D`、`B25J` | `09-03` |
| 名称 | `杯盖` | 品牌或整句广告语 |

发明（流程图等）写手段与用途短词，分类号用 IPC 前缀。`and` 前后留空格。可用 `derived_query.join_and(["折叠", "杯盖", "密封"])` 检查去重，最终仍以 CLI 字符串为准。

分类号无把握时先不填，看命中再收窄。

## 执行

```bash
python skills/patent-search/tools/cnipa_search.py \
  --title "杯盖" \
  --abstract "折叠 and 密封" \
  --class 09-03 \
  --type design \
  --derived-from image \
  --type-inferred \
  --derived-note "折叠杯盖，顶部有饮口盖"
```

用户已说类型时省略 `--type-inferred`。权要换 `--derived-from claims`，按权要主题给 `--type`。

- 带 `--derived-from image` 或 `claims`，报告才会标注代理检索。
- 仍走高级查询 `#ti` / `#abs` / `#e51`，分页与 `patent_search.md` 相同。
- 对话里先用一两句话说明拟用类型和字段，然后直接检索。用户只要检索式时，停在生成、不调用脚本。

## 核对命中

- 用结果里的 IPC / 洛迦诺与拟用分类号对照；对不上的标「分类号未印证」。外观命中对洛迦诺，实用新型对 IPC。
- 题名或摘要对上至少一部分特征词；只沾边的标「部分特征命中」。
- 面向用户带上脚本写入报告的免责声明。本结果是关键字清单，查新、FTO、侵权筛查另走对应流程。
